Netmiko, from first login to production scripts

Netmiko is a Python library that simplifies SSH (and Telnet) connections to network devices — routers, switches, firewalls — so you can automate things you'd otherwise type by hand into a CLI. Each section below has a short explanation and a minimal, runnable example. Work through them in order, or jump to what you need from the sidebar.

01

FUNDAMENTALS

What is Netmiko

Network devices don't expose clean APIs the way web servers do — most are still managed over an interactive SSH terminal. Netmiko wraps that terminal in Python: it handles the login prompt, disables paging, and gives you plain functions like send_command() instead of raw byte streams.

It supports 100+ platforms — Cisco IOS, NX-OS, ASA, Juniper, Arista, HP, and more — behind one consistent interface.

Installation

Netmiko is a normal pip package. A virtual environment is recommended so it doesn't mix with system Python packages.

# in a terminal
pip install netmiko

Your first connection

Every session starts the same way: describe the device in a dictionary, hand it to ConnectHandler, and you get back a live connection object.

from netmiko import ConnectHandler

device = {
    "device_type": "cisco_ios",
    "host":        "198.18.128.10",
    "username":    "admin",
    "password":    "admin123",
}

connection = ConnectHandler(**device)
print(connection.find_prompt())   # e.g. "Router1#"
connection.disconnect()

Always call disconnect() when you're done — or better, use a with block, shown further down, so it closes automatically.

02

CORE OPERATIONS

Sending commands

send_command() runs a single "show"-style command and waits for the prompt to return, giving you the full output as a string.

with ConnectHandler(**device) as conn:
    output = conn.send_command("show ip interface brief")
    print(output)

Configuration changes

Configuration commands are different from show commands — they need config mode, entered one line at a time. send_config_set() handles that for you and saves the result of the whole block.

config_commands = [
    "interface loopback 10",
    "description Configured by Netmiko",
    "ip address 10.10.10.1 255.255.255.0",
]

with ConnectHandler(**device) as conn:
    output = conn.send_config_set(config_commands)
    conn.save_config()  # "write memory" on IOS
    print(output)

Device types

device_type tells Netmiko which prompt patterns and quirks to expect. Common values: cisco_ios, cisco_nxos, cisco_asa, juniper_junos, arista_eos, hp_comware. If you don't know it in advance, "autodetect" can guess it for you.

from netmiko import SSHDetect

guesser = SSHDetect(**{**device, "device_type": "autodetect"})
best_match = guesser.autodetect()
print(best_match)  # e.g. "cisco_ios"

Enable mode & secrets

Some platforms need a separate privileged ("enable") mode before you can configure anything. Add a secret to the device dictionary and call enable().

device["secret"] = "enable_password"

with ConnectHandler(**device) as conn:
    conn.enable()
    print(conn.find_prompt())  # now ends in "#" not ">"
03

PRACTICAL PATTERNS

Error handling

Two exceptions cover most real-world failures: a timeout during login, and bad credentials. Catching them lets a script keep going instead of crashing on one unreachable device.

from netmiko.exceptions import NetmikoTimeoutException, NetmikoAuthenticationException

try:
    conn = ConnectHandler(**device)
except NetmikoTimeoutException:
    print("Device unreachable")
except NetmikoAuthenticationException:
    print("Bad username or password")

Multiple devices

A list of device dictionaries plus a loop is enough to run the same command across a whole fleet, one connection at a time.

devices = [device1, device2, device3]

for dev in devices:
    with ConnectHandler(**dev) as conn:
        print(dev["host"], "->", conn.send_command("show version"))

Structured output

Raw CLI text is painful to parse. Passing use_textfsm=True runs the output through TextFSM templates and returns a list of dictionaries instead of a wall of text.

result = conn.send_command("show ip interface brief", use_textfsm=True)
print(result[0]["intf"], result[0]["status"])

Requires the ntc-templates package (installed alongside Netmiko's extras) for the matching template to exist.

Reading from a file

In practice, device lists live in a CSV or YAML file, not hard-coded in the script.

import csv

with open("devices.csv") as f:
    for row in csv.DictReader(f):
        with ConnectHandler(**row) as conn:
            print(conn.send_command("show clock"))
04

ADVANCED

Timeouts & delays

Slower devices or heavy commands sometimes need more patience than the defaults allow. read_timeout extends how long a single command waits; global_delay_factor scales every internal wait in the session.

conn.send_command("show tech-support", read_timeout=120)

device["global_delay_factor"] = 2  # slow device, double all delays

SSH key authentication

Password can be swapped for a private key file — useful for devices set up with key-based auth instead of passwords.

device = {
    "device_type": "cisco_ios",
    "host":        "198.18.128.10",
    "username":    "admin",
    "use_keys":    True,
    "key_file":    "/home/user/.ssh/id_rsa",
}

Concurrent connections

Looping through devices one by one is slow at scale. A thread pool lets Netmiko talk to many devices in parallel, since each connection just waits on network I/O most of the time.

from concurrent.futures import ThreadPoolExecutor

def get_version(dev):
    with ConnectHandler(**dev) as conn:
        return dev["host"], conn.send_command("show version")

with ThreadPoolExecutor(max_workers=10) as pool:
    results = list(pool.map(get_version, devices))

Session logging

When something misbehaves, a raw session log of every byte sent and received is the fastest way to see what actually happened on the wire.

device["session_log"] = "netmiko_session.log"

Best practices

A short checklist for production scripts:

— Use with ConnectHandler(...) so connections always close, even on error.
— Keep credentials out of source code (environment variables or a secrets manager).
— Wrap connections in try/except so one bad device doesn't stop the whole run.
— Prefer send_config_set() over sending raw config lines with send_command().
— Use threading only after single-device logic is solid and tested.

Netmiko is open source and documented at github.com/ktbyers/netmiko — this page covers the parts you'll use day to day, not the full API surface.
